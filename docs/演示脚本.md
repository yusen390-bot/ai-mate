# AI Mate 演示脚本（约 5 分钟）

## 0. 准备（30 秒）

- 双击 `启动AI-Mate-双击我.cmd`，或 `npm run dev`
- 打开 http://localhost:5173
- 顶部应显示「后端在线」「deepseek-chat 已配置」

## 1. 讲定位（30 秒）

> AI Mate 不是一个聊天框，而是「**目标 → 计划 → 确认 → 执行 → 验证 → 持久化**」的任务协作系统。
> 模型只提出计划或工具调用请求；**状态由后端程序控制**；任务是否完成由**验证器规则**判定，不采信模型自评。

## 2. 建项目 + 生成计划（1 分钟）

1. 左侧填：标题「向量数据库技术报告」，目标「帮我整理一份关于向量数据库的技术主题报告」
2. 点「用 AI 生成计划」→ 展示 6~8 个子任务、依赖关系、完成标准
3. 点「编辑计划」：改一个任务标题；给**最后一个任务勾上「需人工审批」**；点「保存计划」
4. 强调：保存后项目状态是「**待用户确认**」，此时**不会执行任何任务**

## 3. 确认执行 + 审批（1 分钟）

1. 点「确认执行」→ 任务逐个变成「已完成」
2. 执行到需审批的任务时：任务变「待人工复核」，项目变「待用户确认」
3. 点「批准并继续」→ 项目变为「已完成」
4. 指出底部「执行日志」：每次尝试的状态与错误

## 4. 任务地图 / 工作台（1 分钟）

1. 切到「任务地图」：节点按依赖层级排列，箭头表示依赖，颜色表示状态
2. 点任一任务 → 详情面板：完成标准、工具、尝试次数、执行记录、产物
3. 说明产物落库：`report` 生成 Markdown 报告，`text_check` 生成检查结果 JSON

## 5. 可靠性（1 分钟）

- `npm test` → 展示 50 个左右用例全过
- 讲三类兜底：
  - **模型超时 / API 失败**：模型调用失败自动重试 1 次；仍失败返回 **502 MODEL_ERROR**，服务不崩
  - **非法输出**：Zod 校验 + 依赖环检测 → **422**，**不落库**
  - **服务重启**：`running` 任务转 `needs_review`，**不盲目重跑**（避免重复副作用）
- 重启后端 → 项目状态、执行记录、产物仍在

## 常见提问

| 问题 | 回答要点 |
|---|---|
| 为什么不用 Dify / LangGraph？ | 作业要求自己实现状态机/依赖/验证；现成平台改造成本更高、也无法体现设计能力。我们只借鉴了 checkpoint 与 runs 记录的设计 |
| 模型能不能直接改数据库？ | 不能。模型只产出计划或工具结果，写库、改状态都由后端程序在事务里完成 |
| 怎么保证"真的完成"？ | 验证器用确定性规则（长度/必需章节/检查结果/完成标准），再加用户确认 |
| 失败会怎样？ | 有限重试（默认 3 次）→ 仍失败则任务 failed、项目 failed，可一键重试或重新规划 |
