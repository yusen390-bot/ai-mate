# AI Mate 项目总结

> 项目地址：https://github.com/yusen390-bot/ai-mate
> 技术栈：React 19 + TypeScript + Vite 8 + Tailwind 4 / Express 5 + node:sqlite / Zod / Vitest + Supertest
> 周期：4 周（W1 骨架 → W2 规划 → W3 执行 → W4 集成与演示）

## 1. 项目定位

AI Mate 不是一个聊天界面，而是一个**可运行、可验证、具备完整 Agent 执行闭环的任务协作系统**：

    用户提出目标 → AI 制定计划 → 用户确认 → 系统执行任务
      → 检查执行结果 → 根据反馈继续或调整 → 保存状态并可恢复

边界明确：**不做**通用智能体、不开放任意终端命令/文件操作、不做无限制自主执行。

## 3. 数据模型

| 表 | 作用 | 关键字段 |
|---|---|---|
| `projects` | 目标项目 | id, title, goal, status |
| `tasks` | 子任务 | project_id, title, description, status, **dependencies(JSON)**, **plan_version**, order_index, **requires_approval**, **approved**, **tool**, **acceptance_criteria**, attempts, max_attempts, last_error |
| `runs` | 每次执行记录 | task_id, **attempt**, status, input, output, error, started_at, finished_at |
| `artifacts` | 产物 | task_id, project_id, type, name, content |
| `plan_versions` | 计划版本 | project_id, version, source(model/manual), summary, raw_output |
| `schema_version` | 迁移记录 | version, name, applied_at |

工程细节：外键 `ON DELETE CASCADE`（删项目级联清任务/记录/产物）；WAL 模式；关键写操作走事务。

## 4. 关键设计决策

### 4.1 模型不能直接改状态

**问题**：LLM 输出不可靠，若让它直接决定任务状态，系统无法解释、无法复现。
**决策**：模型只产出**计划**或**工具调用请求**；状态只能由 `executor.ts` 的程序逻辑修改，且每次变更写 `runs`。
**收益**：状态可审计、可回放；模型换供应商不影响流程。

### 4.2 计划用 ref 表达依赖 + 环检测

**问题**：模型不知道数据库 id，无法直接给出依赖。
**决策**：计划中任务用 `t1/t2…` 的 `ref` 表达依赖；落库时做 `ref → 真实 id` 映射；`planRules.ts` 用 Kahn 拓扑排序做**环检测**，非法计划返回 422 且**不落库**。

### 4.3 完成判定用确定性验证器

**问题**：模型"自评已完成"不可信（格式完整但内容不合要求）。
**决策**：`verifier.ts` 用规则判定：
- 输出非空 / 长度达标
- `report`：至少 2 个二级标题
- `text_check`：解析 JSON，`ok === true`
- 任务必须有可验证的 `acceptance_criteria`
**收益**：可复现、可统计通过率；不额外消耗模型调用。

### 4.4 状态流转白名单

**问题**：任意状态跳转会产生"已完成→草稿"这类脏数据。
**决策**：`shared/types.ts` 定义 `PROJECT_TRANSITIONS` / `TASK_TRANSITIONS`；后端校验非法跳转返回 **409 INVALID_TRANSITION**（附 `allowed` 列表）；前端下拉只渲染合法选项。

### 4.5 有限重试 + 失败转人工

**问题**：失败原因不同，不能一律重试。
**决策**：`tasks.max_attempts`（默认 3）控制重试次数；超限标记 `failed` 并记录 `last_error`；项目层面提供「重试失败任务」与「重新规划」两个入口，由人决定下一步。

### 4.6 重启不盲目重跑

**问题**：`running` 任务可能已产生外部副作用（发布、删除、付费），重启后重跑会造成重复操作。
**决策**：启动时 `recovery.ts` 把 `running` 任务转 `needs_review`、对应 `runs` 标 failed、项目转 `awaiting_confirmation`，**等待人工确认**。

### 4.7 迁移机制

**决策**：`server/migrations/NNN_name.sql` + `schema_version` 表，启动时按版本号幂等执行。
**收益**：表结构演进可追溯；新环境一条命令建库；`/health` 暴露 `schemaVersion` 便于排查。

### 4.8 shared 类型单一来源

**决策**：状态枚举、流转规则、DTO（Project/Task/Run/Artifact/Plan）只在 `shared/types.ts` 定义，server 与 client 共用（client 通过 `@shared` 别名）。
**收益**：避免前后端定义漂移。

### 4.9 受控工具注册表

**决策**：任务只能执行 `services/tools.ts` 注册的 3 个确定性工具：
- `report`：生成含章节结构的 Markdown 报告并落 `artifacts`
- `text_check`：检查前置产出的长度/占位内容
- `note`：结构化笔记
`auto` 按标题推断（撰写/正文/定稿 → report；核查/审校/校验 → text_check；其余 → note）。
**收益**：不开放任意执行能力，符合"受控"要求。

### 4.10 与方案书的技术替代（已确认）

| 方案书 | 本项目 | 理由 |
|---|---|---|
| better-sqlite3 | **node:sqlite**（Node 24 内置） | API 等价，免原生编译，不会卡在 node-gyp |
| OpenAI Agents SDK | **自研 Agent 循环 + OpenAI 兼容 HTTP** | 当前模型为 DeepSeek，方案书允许"不兼容时改用普通模型 API"；`model.ts` 是唯一适配点，未来可平滑替换 |

## 5. 工程实践

- **测试**：7 个文件 / **50 个用例**（健康检查、项目/任务 CRUD、状态流转、计划解析与环检测、执行器、审批、重试、恢复、模型失败兜底）
- **隔离**：测试用 `DB_FILE=:memory:`，互不污染；`app.ts` 不打开数据库，便于测试
- **错误规范**：`{ error: { code, message, details } }`；`AppError` → 4xx，`ModelError` → 502，未捕获 → 500
- **前端**：列表 / 任务地图双视图；任务详情面板；执行日志；等待审批横幅；失败任务重试/重新规划入口
- **工程化**：Git 提交规范、`.vscode` 调试配置、一键启动/停止脚本、局域网访问、演示与验证文档

## 6. 实际遇到的困难与解决（可写入报告）

| # | 问题 | 解决 |
|---|---|---|
| 1 | Git 凭据管理器（GCM）是 .NET 程序，**不支持 socks5h 代理**，导致授权失败 | 改用 `credential.helper store` + PAT，绕开 GCM；并把代理探测写进脚本 |
| 2 | PowerShell 5.1 `Get-Content` 用 GBK 读 UTF-8 文件，写回后中文全乱码 | 统一用 `[System.IO.File]::ReadAllText/WriteAllText` + UTF8 编码；补丁脚本改为 Node 写入 |
| 3 | 执行器最初"只要存在待审批任务就暂停"，导致第一个任务还没跑就停 | 改为**先算可执行任务**，只有"即将执行"的任务需要审批时才暂停 |
| 4 | `auto` 工具按标题含"报告"就选 report，导致"明确报告范围"任务产出过短被验证失败 | 收紧规则（撰写/正文/定稿 → report），并丰富报告模板、降低长度阈值 |
| 5 | 状态机不允许 `failed → running`，重试后项目无法恢复执行 | 在 `PROJECT_TRANSITIONS.failed` 中允许 `running`，并补单测 |
| 6 | 重启后 `running` 任务状态悬空 | 增加 `recovery.ts` 启动恢复策略（转 needs_review，不盲目重跑）|

## 8. 局限与后续工作

- **单机单进程**：执行器用内存锁防重入；多实例部署需要分布式锁（如 SQLite 事务锁 / Redis）
- **工具集较小**：目前 3 个确定性工具；可扩展"网页检索""代码执行（沙箱）"等，但需配套权限与幂等设计
- **无鉴权**：适合本机/可信局域网；公网部署前需加登录与会话
- **计划质量评测**：尚未建立 10~20 案例的回归集（方案书第六节），是下一步最有价值的研究点
- **流式输出**：当前模型调用为非流式，长报告体验可优化
