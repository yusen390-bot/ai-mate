## 二、现有代码与方案要求的差距

现有代码（20:53 版本）是一个**聊天演示**：前端是对话界面，后端表结构是 conversations / messages。
方案要求的核心是**任务协作系统**（计划 -> 确认 -> 执行 -> 验证 -> 持久化），因此当前骨架需要改造：

| 方案要求                                         | 现状                          | 需要做                                                                  |
| ------------------------------------------------ | ----------------------------- | ----------------------------------------------------------------------- |
| 数据模型 projects / tasks / runs / artifacts     | 只有 conversations / messages | 重建表结构（含 plan_version、attempt、dependencies、requires_approval） |
| 任务规划（目标 -> 结构化计划，Zod 校验模型输出） | 无                            | planner：模型输出 JSON -> Zod 校验 -> 落库为子任务 + 依赖               |
| 用户确认后才执行                                 | 无（聊天即回）                | 项目状态机：draft -> planning -> awaiting_confirmation -> running       |
| 执行引擎（依赖顺序、状态机、重试、暂停）         | 无                            | executor：按依赖拓扑取任务，写 runs，重试上限与暂停                     |
| 受控工具（报告生成、文本检查）                   | 无                            | tools/：报告生成、结构检查，输入输出落库为 artifacts                    |
| 结果验证器（规则/测试/来源/人工）                | 无                            | verifier：结构规则 + 必需字段 + 用户确认，产出验证结论                  |
| 重启后恢复                                       | 无                            | 恢复策略：running 任务不盲目重跑，转 needs_review                       |
| 前端 任务创建 / 任务地图 / 工作台 / 审批         | 只有聊天页                    | 四个视图（W1 先做任务列表）                                             |
| Tailwind CSS                                     | 手写 CSS                      | 换 Tailwind                                                             |
| Zod 校验                                         | 无                            | 全部 API 入参 + 模型输出                                                |
| Vitest + Supertest                               | 无                            | 业务逻辑与 API 测试                                                     |
| 模型自我评价不采信                               | 无                            | 验证器独立于模型                                                        |

现有聊天接口 /api/chat 建议保留为"模型连通性自检"，不作为产品主路径。

## 三、第 1 周改造计划（可交付物）

目标：可运行的全栈基础骨架 + 任务 CRUD + 测试。

1. 数据库：projects / tasks / runs / artifacts 四表 + 事务封装（node:sqlite）
2. 后端 API（全部 Zod 校验）：
   - GET /health（服务 + 模型 + 数据库）
   - POST /api/projects、GET /api/projects、GET /api/projects/:id
   - POST /api/projects/:id/tasks、PATCH /api/tasks/:id、DELETE /api/tasks/:id
3. 前端：Tailwind 接入 + 任务列表页（创建任务 / 查看列表 / 改状态）
4. 测试：Vitest + Supertest（health、projects、tasks 的创建/查询/更新/删除）
5. 验收：能创建并查看任务；重启后端任务仍在；npm test 与 npm run build 通过

## 四、待确认的两处技术替代

1. better-sqlite3 -> **node:sqlite**（Node 24 内置，免原生编译，API 等价）
2. OpenAI Agents SDK -> **自研 Agent 循环 + OpenAI 兼容 HTTP**（当前用 DeepSeek；方案书允许不兼容时改用普通模型 API）

若要求严格使用方案书中的两个库，请在开工前告知，否则按上述替代实现。
